Personal Copilot V1 - tài liệu vận hành

Hệ thống agent hiện tại đang làm gì?

Repo này xây một Personal Copilot: trợ lý AI chạy qua CLI, đọc và làm việc trong repo hiện tại, có thể phân loại yêu cầu, hỏi duyệt kế hoạch khi rủi ro, gọi model qua OpenRouter, ghi nhớ tri thức vào file, tạo backlog local, chạy kiểm tra sau khi sửa code, rồi trả về Completion Report.

Runtime: Python CLI Model auth: OPENROUTER_API_KEY Repo scope: repo hiện tại Memory: .learnings/ Backlog: .codex/issues/ Verification: uv run --extra dev pytest khi phù hợp
70 test tự động đang pass sau khi sửa lỗi phân loại chat thường và verification bằng uv.
1 repo là phạm vi làm việc của V1. Multi-repo chưa nằm trong bản hiện tại.
3 mức tự động hóa: edit, deliver, auto. Mặc định là edit để giảm rủi ro.
10 issue local mô tả backlog năng lực V1 đã được tạo trong .codex/issues/.

Trạng Thái Thực Tế

đọc từ code và log hiện tại
Đã chạy được

OpenRouter runtime

agent.py dùng OpenAIChatClient với OPENROUTER_API_KEY và https://openrouter.ai/api/v1. Log cho thấy model OpenRouter đã trả lời câu chào.

Đã sửa

Chat thường không chạy test

Trước đó câu xin chao bị coi là technical work và tự chạy pytest. Hiện intake.py đã có loại conversation nên chat thường không kích hoạt verification.

Cần kiểm chứng thêm

Web research

search.py có abstraction Search Provider, nhưng log chưa chứng minh research web end-to-end qua OpenRouter. Dòng “Microsoft hosted web search” cần được chỉnh để không gây hiểu nhầm.

Node Flow Vận Hành

nhìn như workflow n8n: mỗi node nhận input, xử lý, trả output
Trigger 1. Người dùng nhập lệnh

CLI trong console.py nhận text tự do hoặc command bắt đầu bằng /, ví dụ /autonomy, /issues, /approve.

Router 2. Phân loại task

intake.py phân loại thành conversation, technical work, web research, memory work, local issue, secret config, hoặc status page work.

Guard 3. Kiểm tra quyền và rủi ro

autonomy.py giữ mức quyền hiện tại. planning.py quyết định task có cần plan approval trước khi làm không.

Decision 4. Chờ duyệt nếu cần

Task lớn, mơ hồ, hoặc có delivery action như commit/push sẽ dừng lại. Người dùng dùng /approve hoặc /reject.

Agent 5. Gọi model

agent.py build runtime, nối OpenRouter client, instructions, tools và session của Agent Framework.

Tools 6. Chạy capability nội bộ

Tùy route, app có thể tạo issue bằng backlog.py, ghi memory bằng memory_surface.py, hoặc xử lý command trong console.py.

Check 7. Verification

Nếu là technical work, verification.py tìm test/check phù hợp. Với repo này, nó ưu tiên uv run --extra dev pytest.

Output 8. Completion Report

reports.py gom summary, file thay đổi, verification, risk, memory write và delivery action để in kết quả cuối trong CLI.

Tính Năng Hiện Có

những capability đã có code hoặc wiring runtime

1. Chat qua CLI

Người dùng chạy agent-harness, nhập câu hỏi hoặc task. CLI giữ session và in Completion Report sau mỗi task thường.

2. OpenRouter model auth

App dùng OPENROUTER_API_KEY. OPENROUTER_MODEL mặc định là ~openai/gpt-latest nếu không cấu hình khác.

3. Task classification

Yêu cầu được phân loại để chọn flow đúng. Ví dụ: sửa test là technical work; nhớ preference là memory work; tạo backlog là local issue work.

4. Autonomy modes

/autonomy edit, /autonomy deliver, /autonomy auto kiểm soát mức agent được phép làm. V1 mặc định ở edit.

5. Plan approval

Task có commit, push, deploy hoặc rủi ro cao sẽ yêu cầu duyệt. Người dùng xác nhận bằng /approve hoặc từ chối bằng /reject.

6. Memory surface

Tri thức tái sử dụng được ghi vào .learnings/LEARNINGS.md, lỗi vào ERRORS.md, yêu cầu tính năng vào FEATURE_REQUESTS.md.

7. Local issues

Backlog nằm trong .codex/issues/*.md. CLI hỗ trợ tạo, list, xem, đóng hoặc đánh dấu hoàn thành issue local.

8. Verification discovery

Sau technical work, app tự tìm command test/check. Với repo này, command đúng là uv run --extra dev pytest.

9. Session import/export

/session-export và /session-import lưu/khôi phục trạng thái console và session agent.

Giải Thích Thuật Ngữ

các từ chuyên môn dùng trong repo

Agent

Một chương trình dùng model AI để hiểu yêu cầu, quyết định bước tiếp theo, gọi tool, và trả lời. Trong repo này agent chạy bên trong CLI.

Harness

Lớp khung bao quanh model: quản lý session, tool, memory, todo/mode và cách agent tương tác với runtime.

Runtime

Tập hợp object đang sống khi app chạy: config, agent, memory surface, autonomy session, search provider status.

Task Intake

Bước nhận và phân loại yêu cầu đầu vào. Đây là nơi quyết định câu của bạn là chat thường, sửa code, research, hay tạo issue.

Autonomy

Mức tự động hóa. edit cho phép sửa repo; deliver mở thêm commit/push khi được duyệt; auto rộng hơn và rủi ro hơn.

Plan Approval

Cổng duyệt kế hoạch. Agent phải dừng lại, trình bày plan, rồi chờ bạn dùng /approve trước khi làm task rủi ro.

Memory Surface

Nơi lưu tri thức dài hạn bằng file markdown trong repo. Không phải bộ nhớ ẩn; bạn có thể mở file ra đọc và sửa.

Verification

Bước kiểm tra sau thay đổi, ví dụ chạy test. Mục tiêu là không chỉ nói “đã sửa”, mà còn chứng minh bằng command pass/fail.

Completion Report

Báo cáo cuối task: đã làm gì, file nào đổi, test nào chạy, rủi ro còn lại, memory nào được ghi.

Search Provider

Lớp thay thế được cho web search. Ý tưởng là không khóa agent vào một dịch vụ search duy nhất.

Secret

Thông tin nhạy cảm như API key. Repo có module để đọc secret từ env và redact secret khỏi log/output.

ADR

Architecture Decision Record: file ghi một quyết định kiến trúc quan trọng, lý do chọn, và hệ quả.
