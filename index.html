V1 Scope

what this system is for right now
Primary use case

The Personal Copilot helps one Primary User understand, change, review, document, and research software work, while also preserving reusable knowledge inside this repository.

Current Repository only

V1 does not span multiple repos, cloud drives, inboxes, or life-admin systems. Repository knowledge in this repo is the local source of truth.

Work Surface

The CLI is where task intake, planning, verification, and completion reporting happen. This page is informational only and is not the working interface.

ADR Decisions

plain language
1
Replaceable search backend

Web research is mandatory for fresh facts, but the search backend is not permanent. V1 may default to Microsoft-hosted search when available, while the copilot behavior stays provider-agnostic.

2
Single-repo boundary first

Multi-repo support is deferred until the core loop is proven. That keeps repository edits, memory routing, and verification simpler in V1.

Implemented Surfaces in the Repository

based on the current code and docs layout

Runtime and control surfaces

  • src/agent_harness/cli.py and console.py establish the CLI work surface.
  • agent.py, instructions.py, and tools.py define the harness and tool layer.
  • config.py and __main__.py provide entry and configuration wiring.

Decision-backed capability modules

  • search.py represents the search provider abstraction for web research.
  • memory_surface.py represents the repository-backed memory surface.
  • backlog.py, autonomy.py, planning.py, reports.py, secrets.py, verification.py, and intake.py map directly to the V1 workflow vocabulary.

Memory Surface

  • .learnings/LEARNINGS.md stores durable repo learnings and confirmed working preferences.
  • .learnings/ERRORS.md stores recurring failures, root causes, and verified fixes.
  • .learnings/FEATURE_REQUESTS.md stores rough future capability ideas.

Backlog

  • .codex/issues/ is the implementation-ready backlog for local issues.
  • Issues are concrete enough for an agent or another contributor to pick up independently.
  • The backlog is separate from memory; it tracks buildable work rather than durable knowledge.

Autonomy Levels

permission modes defined for V1
E
Edit Mode

The default V1 mode. Repository edits and verification runs are allowed, but delivery actions still need approval or a higher mode.

D
Deliver Mode

The copilot may perform repository edits plus directly requested delivery actions such as commit, push, PR creation, or similar publish steps.

A
Auto Mode

The copilot may choose necessary repository edits and delivery actions inside explicit boundaries set by the Primary User.

Web Research Model

quality bar, not just a tool hook
✓
Mandatory when repo knowledge is missing or stale

V1 should not guess about current libraries, public docs, or outside facts when the repository cannot answer them.

≠
Source Comparison is the default

Relevant sources should be compared, with preference for official or primary documentation and an explicit note when sources conflict.

↺
Search Provider is swappable

The repository behavior should survive a backend change across Microsoft, OpenAI, Tavily, Brave, SerpAPI, or another provider.
